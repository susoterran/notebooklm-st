# 커밋 전략 (rule)

이 규칙은 세션마다 자동 로드되어 **메인 에이전트와 커스텀 서브에이전트 모두**에 적용된다. `/commit` 스킬은 이 규칙을 실행하는 도구이며, 스킬을 쓰지 않고 커밋할 때도 이 규칙을 따른다.

## 메시지 형식 (gitmoji + Conventional Commits)

헤더: `<emoji> <type>(<scope>)<!>: <subject>`

- **type**: `feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `ci` `chore` `revert` `remove`
- **scope**(선택): 영향 모듈 — 예 `✨ feat(auth): …`
- **subject**: **한국어**·명령형("추가" not "추가됨")·마침표 없음·**≤50자**
- **본문**(선택): 제목과 빈 줄로 분리, **무엇을·왜**(어떻게는 코드가 말하게).
  줄바꿈 기준은 **터미널 표시 폭 72칸**이다. 한글은 한 자가 2칸이므로 약 36자에서 접는다.
  본문 **총 길이 상한은 두지 않는다.**
- **파괴적 변경**: 헤더에 `!` 또는 푸터 `BREAKING CHANGE: <설명>`
- **AI 트레일러**: AI가 코드를 생성·수정한 커밋은 마지막 줄에 `Assisted-by: <모델 ID>` 를 붙인다.
  `<모델 ID>` 는 **커밋을 수행하는 에이전트가 자기 자신의 모델 ID로 치환한다.**
  이 문서에 실제 ID를 적지 않는다 — 적는 순간 다음 모델에서 틀린 값이 박힌다.
  이메일·표시 이름·컨텍스트 변형 표기(`[1m]`)는 붙이지 않는다.
  AI를 공동저자로 적지 않는다. `Co-Authored-By:` 는 사람에게만 쓴다.

### type 및 gitmoji 설명
- feat (✨): 새로운 기능 추가. 사용자가 체감할 동작이 새로 생기는 경우.
- fix (🐛): 버그 수정. 의도와 다르게 동작하던 걸 바로잡는 경우.
- docs (📝): 문서만 변경. 코드 동작엔 영향 없음(README, 가이드 등).
- style (💄): 동작에 영향 없는 서식 변경. 들여쓰기·공백·세미콜론 등.
- refactor (♻️ ): 기능 추가·버그 수정이 아닌, 동작은 그대로 두고 구조만 개선.
- perf (⚡️): 성능 개선. 결과는 같지만 더 빠르거나 자원을 덜 씀.
- test (✅): 테스트 코드 추가·수정. 프로덕션 코드는 건드리지 않음.
- build (📦️): 빌드 시스템·외부 의존성 관련 변경(패키지 매니저 설정 등).
- ci (👷): CI 설정·스크립트 변경(예: GitHub Actions 워크플로).
- chore (🔧): 위 어디에도 안 속하는 잡다한 유지보수 작업.
- revert (⏪️): 이전 커밋을 되돌릴 때.
- remove (🔥): 코드·파일·설정을 삭제만 하는 변경.

## 원칙

- **한 커밋 = 하나의 논리적 변경(atomic).** 성격이 섞이면(기능+리팩터, 포매팅-only) 분리한다.
- 제목은 구체적으로("파일 수정" 같은 모호 제목 금지). 모르는 정보는 지어내지 않는다.

## 커밋은 에이전트가 한다

- **커밋에 사람의 승인을 두지 않는다.** 작업이 논리적 단위로 끝나면 에이전트가 바로 커밋한다.
- 커밋은 로컬이고 되돌릴 수 있다. 승인 게이트는 `git push`**와 PR**(원격 반영)에 있다 → `.claude/rules/branch-strategy.md`.
- 자주 커밋해 체크포인트를 남긴다. 잘못되면 되돌리기 쉬워진다.

## 안전 가드레일 (커밋 전 필수)

- **시크릿·키·**`.env`**·대용량 바이너리**가 스테이징됐는지 점검 → 있으면 멈추고 경고.
- 스테이징된 게 없으면 임의로 전체 `add` 하지 말고 무엇을 커밋할지 확인한다.
- 기본 브랜치(`master`) 이슈는 `.claude/rules/branch-strategy.md`를 따른다.
- `git push` **금지**(사람이 한다). `--no-verify`·force 금지.
