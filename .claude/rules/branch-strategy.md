# 브랜치 전략 (rule)

이 규칙은 세션마다 자동 로드되어 **메인 에이전트와 커스텀 서브에이전트 모두**에 적용된다.

## 브랜치 구조

- **단일 브랜치: `master`.** 이 저장소는 1인 학습 프로젝트이므로 통합 브랜치를 따로 두지 않는다.
- 모든 작업과 커밋은 `master`에서 한다. 작업 브랜치로 전환하라고 요구하지 않는다.
- **원격 저장소는 없다.** `git push`할 대상이 존재하지 않는다.

## 지켜야 할 것

- 사용자가 요청하지 않은 `push`는 하지 않는다. 원격이 생기더라도 마찬가지다.
- `--force`·`--no-verify` 금지.
- **원격 저장소 생성·연동은 외부로 나가는 행위**이므로 사용자가 직접 하거나 명시적으로
  지시해야 한다. 에이전트가 임의로 `git remote add`·`gh repo create`를 실행하지 않는다.
- 협업자가 생기거나 배포가 시작되면 이 규칙을 다시 검토한다. 그때는 `develop` + PR 흐름이
  값을 한다.
